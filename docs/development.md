# 开发说明

## 当前可执行操作

当前仓库只含文档及目录骨架，无应用可启动。
安装 Git 后按根 README 克隆仓库即可阅读和编辑 Markdown，无需安装应用依赖。

## 工程初始化顺序

1. 完成 requirements.md 中首版目标、平台、定制规则和验收项。
2. 记录技术选择及原因，包括前端、是否需要后端、数据存储与部署方式。
3. 使用所选方案的官方脚手架；若框架不使用 src/，调整目录说明。
4. 提交依赖清单和对应锁文件，固定运行时及包管理器版本。
5. 如需配置，添加只含占位值的 .env.example，并逐项说明来源、用途以及是否仅服务端可用。
6. 实现最小页面，提供真实有效的安装、开发、构建和检查命令。
7. 在干净环境按文档复现，再开始功能开发。

## 首个工程 PR 必须补齐

- 系统要求及准确版本。
- 依赖安装、环境配置和本地启动命令。
- 本地访问地址、预期页面与正常启动的判断方法。
- 构建与适合技术栈的自动检查命令及实际结果。
- 外部服务不可用时的行为、可使用的脱敏样例。
- 部署目标、发布步骤和必要配置项。

在工程初始化前，这些命令与地址均为未确定，不提供虚构示例。

## 变更验证

本次为文档骨架，无应用测试可执行。检查 Markdown 相对链接、路径与目录用途是否一致。
后续选择技术栈后，再建立覆盖核心流程的测试和 CI；不添加没有实际检查内容的通过型工作流。
