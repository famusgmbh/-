# 下一步 Issue 建议

以下为建议任务，尚未自动创建为 GitHub Issue。按依赖顺序执行。

## 1. 确认首版范围与验收标准（P0）

目的：把“独立站泳帽定制”变为可执行需求。
- 填写 requirements.md 的目标用户、平台、定制规则、预览要求和首版边界。
- 明确项目负责人及需求决策人。
验收：每个必需功能有可测试条件；未决事项有负责人；业务负责人确认范围。

## 2. 收集产品素材与生产规范（P0，依赖 1）

- 盘点首版产品图、Logo、字体、需要时的 3D 模型与 UV。
- 明确印刷区域、尺寸、位置及生产输出格式。
- 确认素材授权和是否允许公开提交；不公开的素材使用外部受控存储。
验收：素材清单包含版本、来源与授权状态，生产规范有参考图或样例，缺项被明确列出。

## 3. 选择技术方案与平台接入方式（P0，依赖 1）

- 确认是否接入已有电商平台，以及嵌入方式。
- 决定前端、后端需求、保存方案与部署目标。
- 若涉及交易，确认商品规格、设计标识和订单之间的关系。
验收：提交技术决策文档，列出选项、选择理由、必要权限和配置项名称，不包含密钥。

## 4. 初始化可运行工程（P1，依赖 3）

- 提交最小应用、依赖及锁文件。
- 更新 development.md 的真实启动、构建与检查命令。
- 根据技术栈添加必要检查与 CI。
验收：新环境可按文档安装、启动、构建，检查实际通过；演示页面可访问。

## 5. 实现首个定制完整流程（P1，依赖 1、2、4）

- 按已确认规则实现选择产品、编辑定制内容和预览。
- 若首版包含交易或生产交付，按确认方案传递设计并供商家读取。
- 覆盖非法输入、缺失素材、保存或外部服务失败等场景。
验收：以已确认产品和脱敏样例走通首版流程；预览与生产参考按 已确认 标准核对；记录验证证据。
